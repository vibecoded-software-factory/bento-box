## How to work this list without hallucinating (READ BEFORE EVERY BATCH)

This stack has already been burned by plausible-but-invented work — the two
prior audits spent most of their items REMOVING it (invented properties like
`IdleMonitor.respected`, a fabricated `Polkit` singleton, comments claiming
"MediaRemote offers no seek" while the vendored adapter exported seek, an
exclusive-zone rule attributed to the wrong backend). The protocol that
caught and prevented all of it:

1. **Read the serving side before writing a line.** Every item names a
   consumer (DMS file:line) and an owner repo. Open BOTH. If the fix speaks a
   protocol (DMS Go-daemon channels, niri IPC, a CLI's JSON), fetch the
   REAL upstream shape first — read DMS's QML parser for that reply, the
   upstream Go daemon source, or niri's `niri-ipc` types — and mirror it
   exactly. Never type a JSON shape, method name, enum value, or flag from
   memory. If you cannot find the authoritative shape, say so in the DONE
   note instead of guessing.
2. **Probe before and after.** Before: reproduce the broken state yourself
   (run the `command -v`, send the socket request, grep `/tmp/bento.log`) —
   if you cannot reproduce it, re-read the item, do not "fix" what you
   cannot see. After: verify with OS ground truth, never "the code looks
   right". Ground truths used so far: `command -v` on the launchd PATH dirs,
   raw socket probes with python (`/tmp/dms-darwin.sock`,
   `/tmp/nigiri-msg.sock` — one JSON line in, one out), `pmset`,
   `system_profiler`, `fc-list`/`ls` for assets, the live shell log, and a
   throwaway QML dump run with `./build/src/quickshell -p <dir>/shell.qml`
   that prints values via `console.log`. A fix without a passing probe is
   not DONE.
3. **QML dump gotchas (learned the hard way):** singletons construct lazily
   and connect async — touch the object in an early Timer and READ it in a
   later one, or you will "verify" an empty state. Signal existence checks:
   `typeof obj.signalName === "function"`. Type registration lives in
   `build/qml_modules/<URI>/*.qmltypes` (the `.qt/qmltypes` intermediates
   are EMPTY — grepping them proves nothing).
4. **Honest failure beats fake success.** If macOS cannot do something,
   the fix is an inert stub that says so (code comment + PORT.md/README) or
   a clean hide — NEVER a shim that fakes a success exit, invents data, or
   returns an empty-but-OK shape the UI will render as truth. If a shim
   cannot serve a subcommand, exit nonzero with a message. If a daemon
   cannot serve a method, return the protocol's error shape.
5. **Edit mechanics that prevent silent corruption:** modify files with
   python heredocs asserting the exact old text (`assert old in src`) so a
   stale assumption fails loudly instead of half-applying; when an assert
   fails, `grep` the actual bytes — do not "fix" the assert by loosening it.
   `clang-format`/`swift-format` after edits; builds must stay warning-free.
6. **DMS is read-only, and so is its behavior.** If a fix seems to require
   changing DMS, the fix is wrong — find the seam in bento/dms-darwin/
   nigiri/glue. Do not "improve" DMS behavior either: if DMS hides a widget
   when a capability is absent, announcing the capability without serving
   the FULL method set DMS then calls is worse than leaving it hidden.
7. **Scope discipline.** One batch = the items you announced, nothing else.
   No drive-by refactors, no "while I'm here". New problems discovered
   mid-batch get REPORTED as candidate items, not silently fixed or
   silently ignored. The checklist is frozen: descriptions never change,
   resolution notes say what was actually done and what was NOT verified
   (e.g. "needs a fullscreen app to confirm visually").
8. **Decision items (API-1, API-5, API-6, DPR-14) belong to the user.**
   Present the options with their real costs; do not pick unilaterally, and
   do not implement the fragile option (private DBs, FDA-gated scrapers)
   without an explicit ask.
9. **When a claim in THIS document contradicts what you find, trust the
   code and say so.** The audit was agent-generated and verified by
   sampling; an item may be partially wrong (one prior-audit finding was:
   `reloadableId` misattributed). Correct the record in the DONE note —
   that is fidelity, not failure.
10. **Report at every batch close: the COMPLETE list, all 42 items, with
    ✅/⬜ and short resolution notes.** Never summarize instead, never defer
    it, never offer to show it — show it. This rule has been violated
    twice before and the user was rightly angry both times.

## Port-project strategy (decided 2026-07-24)

The `dms`-CLI and companion tools split three ways. Match the fix to the kind:

- **Already macOS-native upstream → install the real binary.** `dgop` is
  officially cross-platform and ships signed `dgop-darwin-*` release
  binaries (BIN-1). Always check this FIRST: `gh release view -R
  AvengeMedia/<tool>` for a `*-darwin-*` asset before porting or shimming.
- **Genuinely Linux/Wayland-coupled → a real port project** (the bento-box
  model), in Go where it lets us reuse upstream's schema types verbatim:
  - `dsearch` (danksearch): Linux-only releases → `dsearch-darwin` (mdfind-
    backed) — BIN-7.
  - `dcal` (dankcalendar): Linux/FreeBSD-only releases → `dankcal-darwin`
    (EventKit-backed, speaks dcal's socket protocol) — BIN-8.
  - the `dms` CLI's `matugen queue` / `keybinds` / `config` (live in
    `DankMaterialShell/core`, deeply Wayland-coupled, won't build on darwin)
    → `dms-cli-darwin`, a slim Go module importing the PORTABLE upstream
    packages (`core/internal/{matugen,keybinds,dank16,config}`) and swapping
    the Linux bits — BIN-2/3/12.
- **Trivial OS adapters → glue shims in `install.sh`** (not tools, 3-line
  wrappers): `xdg-open`->open, `gsettings color-scheme`->osascript,
  `notify-send`->osascript, `getent`->dscl, `blur check`->unsupported,
  `color pick`->nigiri, trash->Finder. Already done: BIN-9/11/13/15/16/17.

Owners in the checklist below are pre-port; they shift to the port repos as
those are created (matugen/keybinds -> dms-cli-darwin, etc.).
